# 首个可演示主流程

本文档同时覆盖：

- Django Web 端演示
- Flutter Android App 端演示

## 准备

### 1. 后端启动

在已激活 `sports_stadium` 环境后执行：

```powershell
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 0.0.0.0:8000
```

Web 访问地址：`http://127.0.0.1:8000/`

Android 模拟器访问 API 地址：`http://10.0.2.2:8000/api`

### 2. App 启动

```powershell
cd D:\0Sports_Stadium\mobile_app
flutter pub get
flutter run -d emulator-5554
```

如果界面与代码不一致，先执行：

```powershell
flutter clean
flutter pub get
flutter run -d emulator-5554
```

## App 端演示脚本

### 1. 普通用户主流程

1. 打开 App，使用普通用户 `18800000003 / DemoPass123` 登录。
2. 进入场馆列表页，确认可以看到公开场馆。
3. 搜索目标场馆，例如“演示综合体育馆”。
4. 进入场馆详情页，查看：
   - 场馆基本信息
   - 场地列表
   - 可预约时段
   - 已审核评论
5. 在任一可预约时段点击“预约”，确认提交。
6. 回到首页，进入“我的预约”。
7. 确认新预约状态为“待审核”。
8. 回到场馆详情，提交一条新评论。
9. 进入“我的评论”，确认可以看到自己的评论，并可执行删除操作。
10. 进入“个人资料”，确认角色、账号状态、刷新资料、退出登录可用。

### 2. 场馆管理员主流程

1. 退出普通用户，使用场馆管理员 `18800000002 / DemoPass123` 登录。
2. 确认首页可见：
   - 我的场馆
   - 预约审核
3. 进入“我的场馆”，查看已有场馆及审核状态。
4. 任选一个已审核通过且开放中的场馆，进入场地管理。
5. 在场地管理页确认可以：
   - 新增场地
   - 编辑场地
   - 停用场地
   - 删除场地
6. 进入某个场地的时段管理页，确认可以：
   - 新增时段
   - 编辑时段
   - 删除时段
   - 看到冲突校验错误提示
7. 返回首页，进入“预约审核”。
8. 处理普通用户刚刚提交的预约，点击“通过”或“驳回”。
9. 如需验证删除申请流程，可在“我的场馆”中提交删除申请。

### 3. 系统管理员主流程

1. 退出场馆管理员，使用系统管理员 `18800000001 / DemoPass123` 登录。
2. 确认首页可见：
   - 场馆审核
   - 评论审核
   - 用户管理
3. 进入“评论审核”，处理普通用户刚刚提交的待审核评论。
4. 返回首页，进入“用户管理”：
   - 搜索手机号或昵称
   - 查看角色和状态
   - 编辑非当前系统管理员用户
5. 进入“场馆审核”，处理待审核场馆或删除申请。

### 4. 回切普通用户验证结果

1. 再次使用普通用户登录。
2. 进入“我的预约”，确认预约状态已变化。
3. 进入场馆详情页，确认：
   - 只有已通过评论会公开显示
   - 未通过评论不会出现在公开评论列表中

## 常见问题排查

### 1. 模拟器访问后端失败

- 确认 Django 使用 `python manage.py runserver 0.0.0.0:8000`
- 确认 `.env` 中 `ALLOWED_HOSTS` 包含 `10.0.2.2`
- App 端 API 基地址应为 `http://10.0.2.2:8000/api`

### 2. App 界面和代码不一致

执行：

```powershell
cd D:\0Sports_Stadium\mobile_app
flutter clean
flutter pub get
flutter run -d emulator-5554
```

### 3. 登录页没有回到空密码状态

- 当前实现会记住上次登录账号
- 是否记住密码由登录页复选框控制

### 4. 管理员入口看不到

- 先到“个人资料”页确认当前登录账号角色
- 如角色正确但界面没刷新，重新启动 App

## 预期演示重点

- 三类角色入口清晰，功能边界明显。
- 普通用户能完成浏览、预约、评论、查看个人资料。
- 场馆管理员能维护自己场馆资源并审核自己场馆下的预约。
- 系统管理员能处理平台级审核与用户管理。
- 已取消、未通过、未审核内容不会错误出现在公开主流程中。
