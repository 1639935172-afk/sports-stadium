# 体育场馆预约系统 App 端任务拆分

本文档用于单独跟踪 Flutter / Android App 端开发任务。任务来源对应 `docs/TASKS.md` 中已完成或规划的 Web / 后端任务 1-15，并结合当前移动端已完成的登录、场馆列表、场馆详情能力继续拆分。

## 当前基础

- Flutter 项目已创建：`mobile_app/`
- 已接入 HTTP 客户端：`dio`
- 已接入本地登录状态保存：`shared_preferences`
- 已完成登录、注册、启动恢复登录、退出登录
- 已完成场馆列表与搜索
- 已完成场馆详情、场地与可预约时段展示
- 已新增个人资料展示页，但修改资料、修改密码、注销账号仍需要后端 API 补齐

## App 任务 A1：项目骨架与运行环境

**对应 Web / 后端任务**: 任务 1

### 目标

建立稳定的 Flutter Android 开发、调试和打包基础。

### 已完成

- 创建 `mobile_app/`
- 接入 Android 模拟器 `emulator-5554`
- 配置 Flutter 访问本机 Django API：`http://10.0.2.2:8000/api`
- 安装 `dio`、`shared_preferences`

### 待补充

- 整理 App 端环境说明到文档
- 明确 Debug / Release API 地址配置方式
- Android 打包前检查应用名称、图标、权限和网络配置

### 已完成

- 个人资料页展示角色

### 待实现

  - 普通用户
  - 场馆管理员
  - 系统管理员

- 场馆管理员后续可展示场馆、场地、时段、预约审核入口
- 系统管理员后续可展示审核与用户管理入口

## App 任务 A4：个人资料、修改密码与账号注销

**对应 Web / 后端任务**: 任务 4

### 目标

App 端对齐 Web 的个人资料页面和账号管理能力。

### 已完成

- 新增个人资料展示页
- 展示手机号、昵称、角色、账号状态
- 支持刷新资料
- 支持退出登录
- `PATCH /api/profile/`：修改昵称等资料
- `POST /api/password/change/`：修改密码
- `POST /api/password/reset/`：找回密码
- `POST /api/account/cancel/`：注销账号
- 修改资料表单
- 修改密码表单
- 找回密码流程
- 注销账号确认页
- 注销成功后清除本地登录状态并回到登录页

## App 任务 A9：提交预约与我的预约

**对应 Web / 后端任务**: 任务 9

### 目标

普通用户能从场馆详情页选择时段并提交预约，随后查看自己的预约记录。

### 已完成

- 详情页可点击可预约时段
- 提交预约：`POST /api/reservations/`
- 提交预约前确认
- 提交成功提示“预约已提交，等待场馆管理员审核。”
- 提交后刷新场馆详情，避免已占用时段继续显示
- 提交失败展示错误提示
- 我的预约入口
- 我的预约列表：`GET /api/reservations/mine/`
- 预约记录展示场馆、场地、日期、时间、状态
- 预约状态中文展示：待审核、已通过、已驳回、已取消

### 待优化

- 提交失败时解析并展示后端返回的具体校验错误
- 我的预约列表按时间或状态筛选
- 从提交成功提示直接跳转到我的预约

## App 任务 A15：App 上线前诊断与测试清单

**对应 Web / 后端任务**: 任务 15

### 目标

在打包或演示前，确认 App 与 Django API 的核心流程稳定。

### 检查项

- `flutter analyze`
- Android 模拟器启动正常
- Django 服务使用 `0.0.0.0:8000` 启动
- `.env` 中 `ALLOWED_HOSTS` 包含 `10.0.2.2`
- 登录、注册、恢复登录、退出登录正常
- 场馆列表、搜索、详情正常
- 场地存在但无时段时仍展示场地
- 无后端服务时显示可理解的网络错误
- 普通用户不能访问管理员功能
- 预约冲突由后端最终拦截
- 打包前检查 Android 网络权限和 Release API 地址
